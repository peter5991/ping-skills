# 路演载体指南:PPT 与网页演示页

路演的内容逻辑(结构、节奏、法则)与载体无关——**内容设计先行,载体制作后置**。本文件讲两种载体的制作规范。

> **来源声明**:PPT 部分来自双创国培培训内容;**网页(HTML 演示页)部分是基于路演通用原则的载体延伸推导**(培训未直接讲),标注为【延伸】。用户实践以网页替代 PPT 做主陈述,网页部分按"PPT 逻辑 + 网页可承载更多动态效果"的原则展开。

---

## 一、载体选择矩阵【延伸】

| 场景 | 推荐载体 | 原因 |
|---|---|---|
| 网评提交 | PPT/PDF + 视频 | 网评系统只收规定格式;网页内容用于网评须录制成视频(1 分半定生死,音乐开头即高潮) |
| 现场路演,产品交互演示重(软件/平台类项目) | 网页 | 可直接嵌入可操作 demo、实时数据可视化,演示说服力远超截图 |
| 现场路演,数据可视化和叙事冲击要求高 | 网页 | 滚动叙事、动效、大字号全屏图的表达上限更高 |
| 场地设备未知、时间紧、团队无前端能力 | PPT | 兼容性最稳,评委习惯,修改成本低 |
| 挑战杯等明确"PPT 不必漂亮、更看干货"的赛事 | 均可,内容为王 | 别在载体上过度投入,警惕"PPT 选美"式内卷 |

无论哪种载体:**准备离线兜底方案**——网页导出备用 PDF 或全程录屏视频;PPT 另存 PDF。黑屏死机时,内容还在就能讲。

## 二、两种载体共用的内容逻辑

1. **一页(屏)一论点**:金字塔原理——每页 1 个主旨句(15-20 字),≤3 个分论点,各配数据论据。
2. **一屏 = 一页的映射**:网页的每个满屏 section 对应 PPT 的一页,叙事顺序不变(封面→背景→痛点→调研→方案→技术→竞品→模式→团队→成果→成长→收尾)。
3. **8 分钟节奏**:开场≤1 分钟,解决方案留足时间,荣誉媒体报道 1-2 秒带过。网页按 section 预估停留秒数,讲稿时间标注对应到屏。
4. **开场即高潮**:首屏就要有冲击力(视频、数字、强视觉),不铺垫。
5. **证据链视觉化**:调研照片、合同发票、招投标截图、检测报告——直接呈现,不大段转述。
6. **导航条 = 目录**:页面顶/底部固定导航,让评委随时知道讲到哪(评审"一拖就知道分数",结构清晰本身就是分数)。
7. **图片库先行**:先整理全部图片素材、明确每张图的用意,再做页面。

## 三、PPT 载体规范

- **页数口径**:路演 PPT 克制页数、内容为王;网评 PPT ≥50 页才能展示充分;挑战杯等赛事有正文页数硬限(以当年通知为准)——厚度靠"正文+附件支撑材料"做(金奖范本:正文四五十页+支撑材料共 146 页)。警惕"PPT 选美"(卷到几百页、花一两万外包),内容干货才是分数。
- **视觉**:拒绝千篇一律科技蓝;主色贴合项目调性(标杆案例:红糖馒头项目全 PPT 黑白两色);封面体现"学校很牛、学生很牛"。
- **页面细节**:负责人页做减法(像雷军发布会);荣誉红白对比重点标识;图表用自带工具画(第三方软件有底色水印);画好的图留存作下一届素材。
- **兼容**:确认现场屏幕 4:3 还是 16:9;字体内嵌或转图片;视频单独备份。

## 四、网页(HTML 演示页)载体规范【延伸】

网页替代 PPT 做主陈述:**内容逻辑完全沿用 PPT 体系,表达手段利用网页的动态能力放大**。

### 4.1 信息架构

- **滚动式长页 = 线性叙事的网页映射**:每屏(section)满屏,一屏一论点,滚动即翻页;配合键盘方向键/滚轮逐屏切换,保证演讲者可控节奏。
- **固定导航条**:顶部或侧边锚点导航,对应 17 模块的主线章节,点击可跳(答辩提问环节快速定位到证据页,这是网页相对 PPT 的独特优势——评委问"财务怎么算的",一键跳到财务屏)。
- **首屏 = 封面页**:项目名+主副标+强视觉(视频背景或产品主视觉),一打开即高潮。
- **提问环节设计**:把附录级证据(招投标流程、检测报告、财务明细)做成导航末端的"证据区"屏,平时不讲,被问随时调出——"人无我有"的附录策略在网页上更好用。

### 4.2 动态效果运用原则

动效为叙事服务,不为炫技。评委注意力是稀缺资源,**每处动效必须回答"它帮评委理解了什么"**。高价值场景:

| 叙事场景 | 动效手段 | 服务的法则 |
|---|---|---|
| 痛点呈现 | 数字滚动计数(19 分钟/11 公斤/550 度逐个砸出)、前后对比滑块 | 痛点不痛,刚需不刚 |
| 数据与成果 | 增长曲线动画、计数器、柱状图分色生长 | 参数翻译成收益 |
| 技术原理 | 工艺流程分步高亮、原理示意图动画、3D 模型旋转 | 术语变比喻、原理变动作 |
| 产品演示 | 嵌入可交互 demo/视频、功能逐项点亮 | 方案行不行,亲手可见 |
| 项目历程 | 横向时间轴随滚动推进,失败节点如实呈现 | 有组织科研、真实性 |
| 开场与收尾 | 首屏视频/动效冲击,尾屏金句淡入呼应首屏 | 开场即高潮、情怀收尾 |

**克制红线**:一屏至多一个主动效;动效时长 ≤1 秒(滚动驱动除外),不能拖慢 8 分钟节奏;不用与内容无关的粒子/光效背景(评委看的是内容,动效喧宾夺主即"PPT 选美"的网页版)。

### 4.3 技术红线与现场兜底

路演现场是不可控环境,网页载体必须做到:

1. **完全离线**:单文件或本地目录直接双击可开;零外部 CDN/字体/图片依赖,全部本地化——现场断网也必须能讲。
2. **性能红线**:只动画 transform/opacity(不触发布局重排);单一动效主控库,不堆多个动画库;目标现场普通办公机 60fps。
3. **投屏适配**:按 16:9 设计,1920×1080 为基准;提前确认屏幕比例(4:3 场地要有方案);字体随页面打包,不靠系统字体。
4. **演讲者控制**:键盘逐屏切换;当前屏进度可见(第几屏/共几屏);不设自动播放(节奏必须在演讲者手里)。
5. **三重备份**:①备用机预装同一离线包;②导出静态 PDF(每屏一页);③全程录屏视频。任何一层挂了,路演继续。
6. **提前实测**:在比赛现场或同型号设备上完整过一遍,含切换、视频、demo 环节——"准备、准备、再准备"对网页载体意味着连浏览器版本都要确认。

### 4.4 网页 demo 与主陈述的衔接

产品/MVP 演示平台(如大屏展示站)是路演中的 demo 环节,不是主陈述载体本身:

- 主陈述网页讲逻辑,demo 平台证明真实——两者分开做,demo 环节切屏展示,讲完切回主线;
- demo 必须有"断网/接口挂掉也能演"的预置数据模式;
- demo 时间计入 8 分钟总盘,提前演练切换流畅度;
- 没有真产品可用录屏视频替代实时 demo,但要标注为演示视频(真实性红线)。

## 五、载体自检清单

**PPT**
- [ ] 页数符合赛事口径;附件支撑材料成册
- [ ] 无科技蓝套路;每页一论点;图表无第三方水印
- [ ] 字体内嵌、视频备份、屏幕比例已核实

**网页**
- [ ] 内容结构与 PPT 逻辑一致(一屏一论点、8 分钟节奏)
- [ ] 每处动效都能回答"帮评委理解了什么";一屏至多一个主动效
- [ ] 完全离线可开;无外部依赖;16:9 适配;字体内嵌
- [ ] 键盘可控逐屏切换;无自动播放;屏序进度可见
- [ ] PDF 导出 + 录屏视频 + 备用机三重备份就绪
- [ ] demo 有预置数据兜底;提问环节证据区可一键跳转
- [ ] 已在现场或同型号设备完整实测一遍
