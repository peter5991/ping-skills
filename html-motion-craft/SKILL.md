# HTML 动效选型与执行规范

为 HTML 演示页/落地页选择并实现动画效果时，按本 skill 执行。目标：**选最少的库、用最省的性能、交付断网能开的产物**。

## 硬性红线（每次执行必查，不可妥协）

1. **一个动画职责只保留一个主控库。** 禁止 GSAP、AOS、ScrollReveal、Anime.js 等多套滚动/动画控制器并存操作同一元素或同一滚动进度。选定了就只用它。
2. **动画属性只用 `transform` 与 `opacity`。** 持续动画禁止 `width`、`height`、`top`、`left`；`filter`、`clip-path` 仅在一次性/短促效果中谨慎使用，且必须在目标设备实测。
3. **所有第三方库本地化交付。** 产物不依赖任何 CDN，断网双击 HTML 必须能完整运行。库文件随产物走（本地相对路径或单文件内联）。
4. **简单效果优先原生 CSS。** `@keyframes` / `transition` 能解决的（入场、悬停、循环氛围），不引任何库；只有 CSS 难以表达时才升级 WAAPI 或动画库。
5. **排除项**：p5.js（LGPL，商用交付不友好）、旧 particles.js（已停更，粒子用 tsParticles）。

## 执行流程

1. **确认场景类型**（见下方决策树），必要时先问用户：分页演示还是滚动长页？是否需要 3D？目标环境是否有网？
2. **查效果清单选型**：`references/effects-catalog.md` 按「演示骨架 / 科技氛围 / 信息呈现 / 交互反馈」分类列出 33 项效果，每项标注推荐实现与性能注意点。
3. **检查库本地化**：产物目录下是否已有所需库的本地副本？没有则运行 `scripts/fetch-libs.mjs`（需 Node 18+）按 `references/libs.md` 的已核实版本下载。**禁止**在交付产物中写 CDN 链接。
4. **写代码**：遵循红线；引入的每个库都要能回答"为什么是它"。
5. **验收**（见文末清单），不通过不交付。

## 场景决策树

| 场景 | 方案 |
|---|---|
| 分页式演示（网页 PPT） | **reveal.js** + 内置 Fragment/Auto-Animate + CSS 动画；精细编排再补 GSAP |
| 滚动叙事长页 | **GSAP + ScrollTrigger + Lenis**；图表用 **ECharts** |
| 3D 震撼开场/产品展示 | **Three.js**，由 GSAP 驱动镜头与对象动画；3D 只用于增强主题表达的关键段落 |
| 2D 酷炫特效（粒子爆发、大量精灵） | **PixiJS**（WebGL 加速）；少量粒子/星空可用 tsParticles |
| 手绘风图表/涂鸦元素 | **Rough.js** |
| 复杂预制矢量动效（图标/吉祥物） | **Lottie**（设计师 AE 导出 JSON，本地化播放器+JSON） |
| 触摸滑动/轮播 | **Swiper** |
| 滚动触发简单入场 | **Intersection Observer + CSS transition**（原生零依赖，优先于 AOS/ScrollReveal） |
| React 技术栈 | 界面动效用 **Motion**，3D 用 **React Three Fiber + drei**；不为动效单独引入 React |
| 空间化非线性叙事（Prezi 风） | impress.js，仅在确有表达价值时采用 |

## 验收清单（交付前逐项过）

1. 断网后双击 HTML，所有库与资源正常加载，控制台无 404/加载错误。
2. 全页检查：无多个库控制同一元素/滚动进度；持续动画只动 `transform`/`opacity`。
3. 低性能设备（或 Chrome DevTools 6x CPU 降速）实测：滚动、翻页、3D、图表无明显卡顿。
4. 录屏/路演视角：文字可读、动画节奏不抢内容、关键数据出现顺序正确。
5. 新引入的库已核版本与许可证（MIT/Apache 等商用友好），并登记到项目选型文档。

## 项目专用约束（PPT 定制设计服务项目；其他场景可忽略本节）

以下约束仅服务于特定项目（定制演示设计服务，客户为大学生竞赛群体）：

1. **风格优先级**：深色科技风做完整套；学术风/国潮风各出少量样张。深色科技风完整案例必须体现 Three.js 3D + GSAP 滚动叙事 + ECharts 动态图表三件套。
2. **整页生图"大字少字"**：AI 生图页面只保留大标题级文字，小字正文一律后期叠加文本框（HTML 层覆盖真实文字），防止生图糊字。
3. **虚构内容要仿真**：竞赛高频选题 + 毛边数据（非整数）+ 一句话项目背景。
4. **验收对齐项目文档**：`docs/HTML演示技术手段-2026-09-09.md` §9 与 `docs/组件库选型-2026-09-04.md` 是项目侧的权威版本；如与本 skill 冲突，以项目文档为准并回写修正本 skill。
